# 持续推进

当前本地迭代 v0.2.0，日期 2026-10-29。方向：先把住宅建模路线做扎实，再根据实际任务扩展建筑类型；Windows + Codex，使用现成 SU MCP，不重新开发 MCP。

## v0.2.0 本次推进

- 核对维护者0.4.0发布版、依赖与源码，同步安装、版本混用、旧扩展残留、保存与超时说明；不更改本机安装或配置。
- 新增住宅按需路线：单户／标准层／首层与顶层／指定整栋；重点是共墙、墙板标高、楼梯与板洞、阳台分组和人工修改后的续建。
- 新增原创住宅教学片段的原图DXF、清理参照及示意；一层与自选三层任务分开，不当完整住宅设计。
- 新版提示词不默认完整建模、不限定套餐或SU年份；保留旧包、旧提示词和原CAD准备流程。
- 同版继续完善“圈选截图＋参考样板”的局部修改：目标A／参考B、叠置对象识别、保留尺寸和非目标范围、样板后按授权批量、局部前后对照。来自日常交流，作为方法来源，不计实机验收；聊天原图不进分发包。
- 同版加入 [可选模型分工与交接](../skills/cad-sketchup-mcp/references/model-handoff.md)：Flash做有依据的基础白模，Sol先接手审查再按范围优化；交接当前成果、尺寸红线和问题，接手重读现场，同一时刻只一个Agent写入。附两段提示词，不改模型提供商配置，不假定能力或费用效果已验证。
- 加入项目本地习惯MD和空白模板：只合并明确偏好，保留已有条目、支持纠正／忘记；私人目录排除提交与打包，当前指令与图纸优先。用户授权发布v0.2.0教学试用版并将仓库公开，见 [版本说明](版本说明_v0.2.0.md)。
- 本轮实际文件、几何与桌面推演结果见 [v0.2.0验收](../validation/review-v0.2.0.md)。制作校验阶段不操作真实模型；发布阶段按用户明确授权提交、推送、发试用包并公开仓库。

下一步实机试用优先：独立练习文件中完成一层；人工移动／炸开后只补指定洞口；选择三层任务时核首层入口、阳台与顶层楼梯终止。记录实际工具回读、前后预览、SKP、人工协助与卡点。没有原始记录不宣称通过。

## 反馈怎么记

一条反馈写清：所用版本、进行到哪一步、期望结果、实际结果、脱敏错误或截图、能否复现。图纸尺寸和设计意见由学生确认；AI 分析或示意不冒充图纸事实。

修复只针对实际问题。增加新规则前看是否使学生多问、多等；避免把单个案例尺寸或失败变成所有项目的默认流程。

## v0.1.1 当时的第一次学生试走安排

先找1–2位没用过 SU MCP 的同学，提供当前验收 ZIP，而不是让其复制整个开发仓库。实际安排、联系和软件操作由人决定，本轮尚未发给学生。

可以把这段话与练习包一起发给同学：

> 请按 README 最前面的三个入口，从你现在的状态开始。在自己的学习文件夹和独立空白文件里做“一间房、一个门洞、一个窗洞”的练习，目标是最后保存可编辑 SKP。先只检查现有安装，确需安装或配置时由你决定。遇到不明白的步骤，记下原句、实际现象或脱敏截图，别让 AI 替你编完成结果。结束后告诉我：你从哪一步开始、卡在哪里、最后得到什么文件，以及哪些地方需要别人帮忙。

记录真实现象与文件即可，不先规定必须成功或更快。练习尚未实机导入验证，失败也是需要修教程或核兼容性的反馈，不算已经证明教学无效或有效。

## 修改与验证

1. 修改相应教学源文件，保持主入口简洁，细节放按需教程。
2. 更新相关合成行为场景，重新演练受影响的决策；自动文件检查不能代替演练。
3. 运行 `python scripts/check_and_package.py`，检查文件与生成 ZIP。
4. 实机／学生测试按实际证据更新验证说明；没有执行的继续列待验证。
5. 需要新版本时统一更新版本号、打包脚本和下载入口，复核后再提交。

本仓库不自动安装软件、不自动控制真实模型。进入实机验证前，说明具体目标、文件与影响并取得授权。
