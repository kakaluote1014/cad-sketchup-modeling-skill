# 可选分工：Flash基础建模 → Sol接手审查与优化

适合学生已经能使用不同模型，希望先完成基础白模，再集中处理疑难和局部细节的情况。这里以用户选择的DeepSeek V4.1 Flash与GPT‑6.1 Sol为例，是工作方法建议，不是SU能力排名、兼容保证或节省费用的实测结论。单模型也可按同样阶段完成，不要求购买或切换服务。

## 先把基础阶段做扎实

Flash按 [通用建模规则](modeling.md) 完成本轮有明确依据的墙、洞口、板等构件，先样板后同类批次；住宅任务仍按实际楼层差异处理。比例、目标副本、备份、共享定义、洞口上下墙与人工修改保护从第一阶段就遵守，不留到接手时补做。

交接点由任务状态决定：

- 已授权的基础阶段做完，保存可编辑SKP并给出关键回读、预览与待核项；可转入下一模型集中审查。
- 同一问题修正后仍重复出现，或下一次尝试的影响无法说清：暂停受影响写入，保留最后可靠状态，带着问题交接，不靠反复试错“测能力上限”。
- 进入学生希望重点处理的立面、门窗样式、复杂邻接或其他细节时，可由Sol接手；Flash已经做对的内容保留，不重建整栋。

未知尺寸、设计冲突、错文档或MCP不可用，换模型也不能补成事实或授权。先说明实际缺口，能做的只读工作可以继续；新模型同样需要依据。

## 交接只需一份简短说明

先保护当前内存中未保存的人工成果，按实际能力保存并核验当前SKP。记录当前文件、目标楼层／副本与定位，附上：

- 最新图纸／控制尺寸与设计红线，哪些具体部分允许示意。
- 已完成什么、实际检查了什么，哪些结果只有截图或文字报告、仍未读回。
- 下一步只处理的对象、尚未解决的问题和尝试过的修改；需要时给圈选图及参考样板。
- 当前备份和预览位置；不能安全保存时如实说明，不能宣称已完成交接。

这些内容可写在一段消息或简短MD中，不要求JSON、完整聊天记录或大型审计表。保留原始依据，不把前一模型的推测写成图纸事实。

## 接手后先审查，再按范围修改

Sol先实际读取MCP版本、当前模型和必要组件信息，对应交接的文件、楼层与副本，核对最新现场和相关尺寸。前一聊天的上下文不会自动成为新聊天的知识；旧实体ID、旧几何与“已检查”摘要不代替现场读取。文件不匹配时先定位，已有可用连接跳过安装。

先按本轮范围区分：确定错误、与已给样板不一致、可选美化。每项说明位置、依据、建议动作与需要保留的内容；尺寸或设计依据不足列待核，不用个人偏好重写设计。用户只授权审查时保持只读；另有修改授权则在该范围内推进，不扩大到全模型。

圈选图修改按 [局部修改方法](local-edit.md) 对应真实对象，目标A可参照B，但保留明确要求的尺寸、位置和非目标对象。已授权批次在样板检查通过后连续完成；修完只复查修改项与受影响邻接。按作业要求完成就收尾，可选精修单列，不无限增加细节或承诺费用额度。

同一时刻只让一个Agent写同一模型。交接前确认原写入调用已结束；若超时或可能仍在执行，先等恢复并读实际状态，不启动另一个写入者。明确哪一方继续后再修改。切换模型本身不改变已有API、登录、MCP配置或写入权限，本Skill不代为安装客户端或修改提供商设置。

## 可复制指令一：给Flash做基础模型

> 使用 $cad-sketchup-mcp。这次先用DeepSeek V4.1 Flash完成我指定的基础白模阶段，目标楼层、图纸、尺寸和不可改部分以本聊天最新说明为准。先读现场与相关尺度，保留备份，样板通过后继续已授权同类构件。未知尺寸只暂停受影响部分，不套练习值；每阶段保存可编辑SKP并给关键回读与预览。若同一问题反复出现或无法判断影响，停止相关试改，保留最后可靠状态并说明问题。阶段结束给我一段交接说明：当前SKP与目标、已定尺寸和红线、完成与检查结果、未解决问题、下一步范围、备份和预览；不要假定接手模型知道本聊天。

## 可复制指令二：给Sol接手审查

> 使用 $cad-sketchup-mcp。这次由GPT‑6.1 Sol接手，交接说明、当前SKP及必要圈选图由我提供。请先实际读取MCP版本、模型与必要组件，对照当前文件、目标楼层／副本和相关尺寸，保留人工修改，不用旧ID或重跑基础创建脚本。先只读审查我指定的部分，分清确定错误、样板差异、可选美化和待核项，给具体位置、依据及可复制修复指令；暂不修改。后续获准修改时，按圈选与样板处理，保护其他构件和共享实例，只复查修改项及相邻影响。确认前一Agent已停止写入，保存可编辑SKP并给局部前后对照，未检查的如实列明。

指令里的型号是使用者指定的分工示例，不会自动切换模型；学生在自己的客户端选择实际可用模型。沿用其他组合时，保留上述建模、交接与审查规则即可。
