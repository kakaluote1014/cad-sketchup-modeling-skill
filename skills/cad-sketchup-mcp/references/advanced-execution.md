# 进阶执行细节：按当前问题读取

供 AI 在切副本、批量展开、嵌套编辑或场景交付时读取；学生不必学习 Ruby，也不必准备结构化数据。方法来自用户的骑楼与社区项目经验，API 条目于 2026-10-26 核实。原项目故障不代表所有电脑都会发生；不复制历史脚本、路径或参数。

## 安全保存与切换

先读实际路径、`modified?`、编辑上下文和已获准范围，区分：

- **已有路径、已保存且干净**：可以从已核对的磁盘文件制作字节一致的独立备份与目标副本，再打开目标并重读路径。复制前确认目的地，不能覆盖源件。
- **有未保存修改**：先通过当前支持的保存副本能力，把内存成果保护到明确的独立文件并核验成功；只复制旧磁盘 SKP 不算备份当前状态。MCP0.4.0拒绝对未保存模型导出SKP；先保存到明确的新位置，不能反复重试临时导出，见 [导出实现](https://github.com/zinin/sketchup-mcp2/blob/v0.4.0/mcp_for_sketchup/mcp_for_sketchup/handlers/export.rb)。已有路径模型的临时导出也须转为明确交付位置并核验。

`save_copy` 是 API 的保存副本能力，不能据个别切换事故宣称它总会修改源件。切文件还可能触发客户端、插件或保存提示；未保护内存成果不切换，不擅自覆盖源件或丢弃修改。仍出现保存提示时，确认保护结果并让用户决定提示动作。见 [Model#save_copy](https://ruby.sketchup.com/Sketchup/Model.html#save_copy-instance_method)。

新文件打开后重新定位实体。写入函数内再核对当前路径、目标层级与编辑上下文，发现不符停止本批；外部脚本和 Ruby 目标配置要一致。无法读取必要状态时说明缺口，不以“已配置”代替读回。

重要批次重开交付副本前，先保护当前未保存成果和其他窗口；重开后核对身份、相关尺寸／数量、材质资源及场景。普通改色不反复重开全项目。不能安全重开则列为待核。

## 坐标、单位与结果

外部毫米长度进入原生 Ruby 几何 API 时转换一次 `.mm`，读回长度用 `.to_mm`；已是 Length／已换算的值不重复转换。工具签名已声明 mm 时照签名填写。旋转矩阵的无量纲项不能整体套 `.mm`；原生体积若为立方英寸，转 mm³ 用 `25.4**3`，不是长度倍率。见 [Numeric](https://ruby.sketchup.com/Numeric.html#mm-instance_method)。

比较局部坐标、模型坐标前，明确实例路径并组合各级变换。镜像、旋转、非均匀缩放后，不只比较局部 bbox 或把 bbox 字段名当固定建筑方向。图纸／字段语义不明先核对，不能由平面进深推断设备高度。

读回同时检查协议错误和实际内容；外层成功包住 Ruby 错误文本也算失败。需要结构化结果时按现场工具签名解析并检查字段，不假定所有 MCP 都有同一种字符串包装。可选设备缺失可返回空集合；必要墙组缺失要报错，不能吞掉全部缺失。

## 事务、共享定义与重新定位

先查当前工具是否已封装 operation；已有保护时不机械再开一层。自行管理普通 operation 时配对 start／commit，异常按其规则 abort；只读查询不为此开启写入 operation。SketchUp 不支持嵌套 operation，新开会结束上一个，透明 operation 也不能按普通操作随意 abort。见 [Model 操作说明](https://ruby.sketchup.com/Sketchup/Model.html#start_operation-instance_method)。

局部修改前检查实例、共享父级、嵌套定义和材质共享；隔离本轮不该传播的修改。提案内相同杆件可缓存定义并布置实例，不禁止合理共享。`make_unique`、炸开或重建后重读子对象，检查 `valid?`；需要时新建提案定义并复制源几何。见 [ComponentInstance#make_unique](https://ruby.sketchup.com/Sketchup/ComponentInstance.html#make_unique-instance_method)。

保存重开可能改变运行期实体 ID；以层级、来源标识、名称、位置和可用 persistent ID 共同定位。persistent ID 不保证跨文件、重建或炸开后仍代表同一业务对象。超时先读数量、尺寸和位置；确认已完成就检查保存，部分完成只补缺项，不整批重跑或盲目撤销。

## 场景显隐与遮挡

`Page#layers` 返回在该场景中偏离默认可见性的标签，不是通用“隐藏标签列表”；未保存标签状态时可能为 `nil`。判断显隐还要看标签默认行为、文件夹、对象和祖先隐藏状态、剖切及旧体量遮挡。见 [Page#layers](https://ruby.sketchup.com/Sketchup/Page.html#layers-instance_method)。

新建提案或归档标签时，按要求明确设置相关场景可见性，并检查旧场景保持原显示；仅在当前场景隐藏不算归档完成。替代家具方案互斥。标签设置可用当前版本支持的 `page.set_visibility` 等能力，但要检查场景是否存储该属性；切换后刷新并读实际显示，再导图。不能把 `nil` 一律当“全部可见”或“全部隐藏”。

相机、阴影、标签、剖切分别检查场景保存设置，不默认切场景能恢复全部属性。修改前记相关状态，预览后恢复或保留用户指定的交付场景。不同版本的场景属性与撤销能力需识别，参见 [Page](https://ruby.sketchup.com/Sketchup/Page.html)。

共面闪烁、玻璃不可见先查重复面、遮挡、面朝向、材质透明度与继承；有能力时可用 `raytest` 辅助定位命中对象。优先修正分组与几何；只有明确的图形表现需要才微偏移并记录，不把显示偏移当建筑标高。单面线脚是否改闭合实体依任务决定，没有通用厚度；清线只处理确认多余的零面边、短边或内部接缝，不全局隐藏轮廓掩盖错误。纹理映射尺度与真实斑块大小分开解释，玻璃背板仅作获准的表现选择。

## 指纹与交付边界

文件 SHA256 确认字节身份；保存相机／场景可能改变文件 SHA。几何／属性指纹只比较已声明的面、边、变换、材质等范围；只含几何不证明场景、UV、外部贴图或可编辑性完整。预览和原生回读另行检查。

前后使用相同字段、排序、坐标系和精度。允许修改对象清楚列出，受保护对象分别比较；不扩大忽略范围掩盖误改。浮点差异先保留原始记录并定位，再按相同规则处理正负零或合理舍入；分别说明长度、角度、相机精度，不能把全部差异当噪声。

小任务保留相关尺寸与预览即可；批量展开／重要交付才考虑指纹和保存重开，不要求学生交哈希报告。给一个当前 SKP 入口、预览和短说明；附外部纹理时核对资源可用性及分享范围，不捆绑真实项目、私人配置或未获准的第三方资源。
