# 分阶段建模：学生与 AI 怎么配合

优先 SketchUp MCP，尽量减少 computer use。MCP 无法完成且学生需要界面操作时再用 computer use；缺信息请学生提供图纸、尺寸、标注截图或位置说明。

## 开始或继续，先读现场

每次写入前（包括下一批同类构件）重读：文档标题／路径、实际尺度、目标楼层与副本、选择／编辑上下文、几何位置和变换。学生会复制中间层到旁边做首层／顶层，也会单开 SU 窗口；用文档、选择、位置、层级共同定位，不用旧实体 ID 猜目标。

“右边那个”有歧义请选中或标注，只检查不修改，只做指定楼层和副本。人工移动、复制、炸开、换窗口后重新读取，保留改动，不按旧模型重建覆盖。

底图几何初检、尺度存疑或几何尺寸修改前，核对两段有依据尺寸。每次写入仍重读文档、目标、变换和尺度状态。只调颜色／透明度且不改几何、不依赖物理尺寸时：已有同文档校验记录且目标与变换未变，可沿用，不重新索要尺寸；没有记录就如实标“几何尺寸未校验”，在身份、材质分类、共享影响与备份检查通过后仍可继续这项颜色／透明度修改，不据此宣称尺度正确。涉及纹理的物理尺寸或任何几何变化仍需尺寸校验。MCP 的 units:mm 只是输出单位；已有多层成果不能自动全模型缩放，先查原因、说明影响与确认修正范围。

给 AI 的最小信息：

- 目标楼层／副本和本次想做的构件。
- 原图或标注尺寸、单位、本阶段必需的墙高／开口等参数。
- 哪些位置未定，是否允许某个具体构件示意。

以最新明确图纸、尺寸和修正为准。新标注、旧口头值与当前几何冲突时，指出具体冲突、核对受影响部分，不重问全部内容。墙高、柱截面、坡道、栏板无通用默认值；旧项目 3m、300×300mm 或“常见尺寸”不能填入未知项。

## 每阶段怎么做

1. 修改前保留当前状态的可恢复备份，包含未保存的人工修改。未命名先保存到明确位置，保存失败停写入。
2. 查询并区分墙线、面、门窗符号和其他区域，查闭合、共面、误封大面，先检查或小范围试做。
3. 先展示样板与实际检查结果。用户已授权整个阶段时，该范围内样板通过客观检查即可继续同类构件；只有用户明确要求“样板给我确认再继续”、关键参数仍冲突或目标改变时才等待确认。普通色调可先按已给方向做样板并标明选择，不把每个可逆细节都变成审批。
4. 墙、门窗、板、栏板、柱独立编组。复制组件局部编辑前查共享定义，包括共享父级；必要时使本次相关实例独立，避免影响别层。独立化后重读，不复用旧子实体。
5. 读回尺寸、数量／遗漏与非目标副本状态，保存阶段 SKP，给预览和短问题清单。

墙线不闭合／不共面时定位缺口／高差，对照原图，依据清楚才局部补齐；不把门洞间隙补死。未知尺寸或错误尺度暂停相关部分，不批量拉高全部面，可继续不受影响的检查。

## 常用顺序与检查点

按实际任务调整；用户只要墙体，到墙体检查、保存结束。首层、标准层、顶层需求不同，不自动加未要求构件。

| 阶段 | 建模依据与重点 | 检查点 |
|---|---|---|
| 墙体 | 墙厚、墙高、基准标高明确；区分地面、门弧、楼梯、电梯、投影 | 样板厚／高、漏墙、误墙、重复、相交、开口边界 |
| 门窗及洞口上下墙 | 位置、宽高、窗台标高；门弧不是实体 | 门上墙、窗上墙、窗台墙齐全；洞口贯通，框与玻璃分开编辑 |
| 阳台／入口坡道 | 玻璃推拉门、楼板、栏板分别表达；坡道长宽、高差、落地点有依据 | 门洞、板、栏板不混；坡道高差、衔接，不猜安全或合规 |
| 柱子 | 截面、标高、柱位按图，含图中墙内柱；无依据不自动布置 | 数量、位置、截面；获准示意标“示意柱”，独立可编辑 |
| 屋顶及排水 | 要求时按顶层图确认形式、坡度、标高、出檐、排水 | 对齐目标顶层、高差／坡度、不影响标准层；分明确与示意 |
| 材质 | 墙体、窗框、玻璃分开，查透明度、前后面、继承 | 内外看玻璃，不统一涂不透明墙色，不误改共享材质 |

洞口竖向关系按同一本层基准：窗台墙高度 = 窗台标高；窗上墙高度 = 墙高 − 窗台标高 − 窗洞高；门上墙高度 = 墙高 − 门洞高。绝对标高、梁、错层、不同墙顶先换算并核对，不直接套用；负值先查冲突。

近似布置须明确允许，限定对象与范围，标“示意／待核”，独立可编辑；一次授权不扩展到其他未知项，示意柱不是结构设计。

## 超时与误操作

超时不代表没执行。等 SU 恢复后重读目标位置、数量、尺寸：已完成检查保存，部分完成定位剩余，无法确定暂停。不要重发同次修改，也不直接 undo，最后一步可能是人工操作。

误改先查当前状态与备份，说明影响，再局部修复或恢复；不恢复旧文件覆盖后续人工改动。同一范围一次一个写入任务，多客户端连接不意味着能同时安全改同一模型。

## 保存、预览与交付

阶段保存可编辑 SKP，确认成功、存在且非空。备份和阶段文件不同名，放学生确认位置，不覆盖原图；旧磁盘文件或空 .skb 不是当前备份。

本版 export_scene 的 SKP 是临时导出，未命名模型还可能改变保存路径。先请学生保存到明确位置，或在获准范围内通过 MCP 保存副本；不把临时导出当最终交付。[导出行为依据](https://github.com/zinin/sketchup-mcp2/blob/v0.3.1/mcp_for_sketchup/mcp_for_sketchup/handlers/export.rb)

预览用现有 MCP PNG 导出；SU 2026+ 可用视口截图。旧版导出当前视图或请学生手工截图，不为截图升级。改变视图要恢复；截图不代替尺寸读回。

AI 先发现现成工具及实际签名，再查询和修改；教程中的动作名称不是新工具接口。能力不足说明限制、给手工步骤，不伪造结果。需要 Ruby 时正确使用毫米和 API 单位转换，考虑嵌套变换；写入调用内目标若已改变就停止，不猜新目标，使用现有事务／撤销保护，出错退出。学生无需学习 MCP 或 Ruby 开发。

反馈 3–5 行：完成什么、关键尺寸实测值、待核项、SKP／备份和预览位置。未检查内容不写完成。

一层白模完成：指定构件齐全，底图与关键构件尺寸可复核，洞口关系正确，目标层独立可编辑、别层保留、SKP 实际保存。示意／待核项继续列明，不声称结构验算或施工合规完成。
